7 Git Habits That Saved Me From Myself

Small, boring habits — atomic commits, --force-with-lease, reflog — that turned Git from a source of panic into a safety net.

Radharaman SethiJun 3, 20266 min read
🌿

Early on, Git was the scariest tool I used. One wrong command and hours of work could vanish — or worse, I'd overwrite a teammate's changes. Over time I picked up a handful of boring habits that turned Git from a source of panic into a safety net.

None of these are advanced. That's the point.

1. Commit small, commit often

An atomic commit does one thing: fix one bug, add one function, rename one file. Small commits are easy to review, easy to revert and easy to understand six months later.

When I've made a mess of several changes at once, git add -p lets me stage them hunk by hunk and split them into clean commits:

bash
# review and stage changes piece by piece
git add -p

# see exactly what you're about to commit
git diff --staged

2. Write commit messages for future-you

"fix stuff" tells you nothing. A good message says what changed and why. I use a short imperative subject line, then a body when the reason isn't obvious:

text
Fix race condition when saving drafts

Two quick saves could finish out of order and overwrite newer
content. Track a version number and ignore stale responses.

3. Never work directly on main

Branches are free. Every feature, fix or experiment gets its own:

bash
git switch -c fix/draft-race-condition

If the experiment fails, delete the branch. Nothing else was touched.

4. Use --force-with-lease, never --force

Sometimes you need to rewrite history on your own branch (after a rebase, for example). git push --force will happily overwrite commits someone else pushed in the meantime. --force-with-lease refuses if the remote has changed since you last fetched:

bash
git push --force-with-lease
⚠️

Only rewrite history on branches that are yours. On shared branches, prefer a new commit (or git revert) over rewriting.

5. Learn to love the reflog

This is the habit that ended my Git panic. The reflog records where HEAD has been — including commits that no branch points to anymore. Did a bad reset? Deleted a branch? Your work is almost certainly still there:

bash
git reflog
# a1b2c3d HEAD@{0}: reset: moving to HEAD~3
# 9f8e7d6 HEAD@{1}: commit: Add search filters   <-- the one I lost

# bring it back on a new branch
git branch rescue 9f8e7d6

Once you know the reflog exists, Git stops feeling like a minefield. Committed work is very hard to truly lose.

6. Stash with a name

git stash is great until you have five anonymous stashes and no idea what's in them. Give them a message:

bash
git stash push -m "wip: half-done navbar refactor"
git stash list
git stash pop stash@{1}

7. Make your aliases work for you

A few aliases I use every day:

bash
git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --decorate --all"
git config --global alias.undo "reset --soft HEAD~1"

git undo is the star: it un-commits your last commit but keeps all the changes staged, perfect for "oops, I forgot a file".

The real lesson

Git rewards people who commit often and read before they run. Pick one habit from this list, use it for a week, then add another. Before long, you'll be the person teammates call when their repo is on fire. 🌿
